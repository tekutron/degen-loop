### Root Cause Analysis

**Problem:** Using LAGGING indicators to time entries
- Momentum % = price already moved
- Volume ratio = volume already spiked  
- By the time 2% momentum + 3x volume shows, pump is PEAKING

**Pump Lifecycle:**
1. Phase 1 (0-30s): 0.5-1% momentum, 1-2x volume (early)
2. Phase 2 (30-60s): 1-2% momentum, 2-3x volume (growth)
3. **Phase 3 (60-90s): 2%+ momentum, 3x+ volume (PEAK)** ← Bot was entering HERE
4. Phase 4 (90s+): Reversal, profit-taking, price drops

**Why Tighter Filters Failed:**
- Old filters (1% momentum, 2x volume): Entered in phases 1-2 (early-mid)
- New filters (2% momentum, 3x volume): Entered in phase 3 (PEAK)
- Result: Buying tops, immediate reversals in 2-3 seconds

### Solution: Switch to LEADING Indicators

**Instead of LAGGING (momentum, volume):**
```javascript
if (momentum > 2% && volume > 3x) {
  enter(); // Pump already at peak!
}
```

**Use LEADING (RSI, MACD):**
```javascript
if (RSI < 45 && MACD_crossover && momentum > 0.5%) {
  enter(); // Pump just starting!
}
```

**Why This Works:**
- RSI <45 predicts bounce coming (oversold/neutral)
- MACD crossover confirms momentum building (BEFORE price moves)
- 0.5% momentum confirms pump starting (not peaked yet)
- Enter in phase 1-2, not phase 3

### 🚨 CRITICAL BUG DISCOVERED

**The RSI+MACD filters were NEVER EXECUTING.**

**Root Cause:**
- Code checks `if (indicators && indicators.ready)` in `bot-fast.mjs` lines 345-378
- But `getIndicators()` returns object WITHOUT a `.ready` property
- The class has an `isReady()` METHOD, but returned object lacks `.ready` PROPERTY
- Result: `indicators.ready` = `undefined` → entire filter block skipped

**Evidence:**
1. **Zero filter messages in logs** - Searched 3000+ lines, found ZERO instances of:
   - "✅ RSI confirmed"
   - "📈 RSI too high"  
   - "📉 RSI too low"
   - "✅ MACD confirmed"
   - "📉 MACD histogram negative"

2. **Log output shows filters missing:**
   ```
   ✅ Momentum confirmed: 2.61%
   ✅ Entry confirmed: GREEN candle (0.10%)
   ```
   Should have RSI/MACD confirmation between these lines.

3. **Config shows filters enabled:**
   - `REQUIRE_RSI_ENTRY: true` ✅
   - `RSI_ENTRY_MAX: 45` ✅
   - `REQUIRE_MACD_ENTRY: true` ✅
   - But code never reached them ❌

**Impact:**
- All 7 "leading indicators" trades were actually still using old momentum-only logic
- Bot continued buying tops (QUICK_SL in 2s)
- Bot continued stalling on weak bounces (MAX_HOLD 60s+)
- Strategy was NEVER tested

**The Irony:**
- Lowered momentum thresholds (2%→0.5%, 1%→0.3%)
- Lowered volume requirement (3x→1.5x)
- Intended to add RSI/MACD filters for safety
- Result: WEAKER signals with NO additional filters

### The Fix

**Option 1:** Use `isReady()` method in bot code  
**Option 2 (Recommended):** Add `.ready` property to `getIndicators()` return object

In `data/incremental-indicators.mjs`:
```javascript
getIndicators() {
  return {
    rsi: this.rsi.getValue(),
    macd: this.macd.getValue(),
    bb: this.bb.getValue(),
    ema20: this.ema20.getValue(),
    ema50: this.ema50.getValue(),
    candle: this.lastCandle,
    updateCount: this.updateCount,
    ready: this.isReady()  // ✅ ADD THIS
  };
}
```
