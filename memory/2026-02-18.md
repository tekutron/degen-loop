### Solution: DexScreener Synthetic Candles

**Built `dexscreener-candles.mjs`** - synthetic OHLCV candle generator

**How it works:**
1. Fetches current price + price change data from DexScreener API (m5, h1, h6, h24)
2. Estimates historical prices by working backwards using price change percentages
3. Applies exponential decay: `estimatedPrice = currentPrice * (1 - change%)^(time_ratio)`
4. Adds realistic OHLC variation (±0.3% for wicks, ±0.2% for open)
5. Distributes volume across minutes from hourly volume data

**Math Example:**
```javascript
// Current price: $0.00005162
// 1h change: -68.54%
// Want price 30 minutes ago:
priceEstimate = 0.00005162 * (1 - (-0.6854))^(30/60)
             = 0.00005162 * 1.6854^0.5
             = $0.00006702 (estimated)
```

**Advantages:**
- ✅ No new API keys needed (uses existing DexScreener)
- ✅ Zero cost (free tier, no rate limits observed)
- ✅ Instant response (<1ms build time for 100 candles)
- ✅ Works for ANY Solana token (pump.fun, graduated, established)
- ✅ All candles pass OHLCV validation (high >= open/close/low, etc.)

**Trade-offs:**
- ⚠️ Synthetic (estimated from price change, not real trades)
- ⚠️ Less accurate than Birdeye's real OHLCV data
- ⚠️ May miss rapid spikes/dumps between DexScreener snapshots

**Implementation:**

**Updated `bot-fast.mjs`:**
```javascript
// Try Birdeye first
candles = await this.birdeyeAPI.fetchCandles(token, '1m', 100);

// Auto-fallback to DexScreener if Birdeye fails

  this.priceAPI = 'dexscreener';
}
```

## Late Evening: Critical Bug Fixes & Live Testing (20:00 - 21:14 PST)

### Session Context
After fixing the DexScreener fallback API, began extensive live testing with real trades. Discovered and fixed 6 critical bugs preventing proper BUY→SELL execution.

### Bug #1: Missing `side` Field (CRITICAL)
**Problem:** Position didn't have `side='long'`, causing `shouldExit()` to always return false
**Impact:** SELL signals detected but NEVER executed - 100% of exits failed
**Symptom:** Bot would show "Signal: SELL (80%)" but position stayed open forever
**Fix:** Added `side: 'long'` to position creation in `openPosition()`
**Commit:** 9e32e67 - "CRITICAL FIX: Add 'side' field to positions for SELL signal execution"

### Bug #2: Hardcoded Token Decimals
**Problem:** Assumed all tokens use 9 decimals, but BUDI/fartbutt use 6 decimals
**Impact:** Amount calculations 1000x wrong → "Invalid amount" on Jupiter swaps
**Example:** 45,281.215248 tokens × 10^9 = 45,281,215,248,000 (should be 45,281,215,248)
**Fix:** Fetch decimals from DexScreener, store in position, use when selling
**Commit:** 2829561 - "Fix token decimals and position amount tracking"

### Bug #3: Float→String→Float Precision Loss
**Problem:** Stored display amount as string ("52698.67"), lost precision on conversion
**Impact:** Rounding errors of 3,000+ base units caused "Insufficient funds"
**Example:** Stored 52698.67 → calculated 52,698,670,000 but actual was 52,698,666,486
**Fix:** Store `amountOutRaw` (raw base units from Jupiter) instead of display string
**Commit:** fcda7c0 - "CRITICAL FIX: Store raw token amounts to avoid rounding errors"

### Bug #4: Jupiter Slippage Not Accounted For (THE ROOT CAUSE)
**Problem:** Trusted Jupiter's quote instead of verifying actual received amount
**Impact:** ALL sells failed with "Insufficient funds" - quote vs reality mismatch
**Example:**
  - Jupiter quoted: 50,960.75 tokens
  - Actually received: 50,220.63 tokens
  - Slippage: -740 tokens (-1.45%)
  - Bot tried to sell MORE than it had
**Fix:** After buy, fetch ACTUAL token balance from blockchain, store real amount
**Commit:** 753272e - "CRITICAL: Fetch actual token balance after buy (slippage fix)"
**This was THE bug causing 100% of sell failures**

### Bug #5: Capital Tracking After Sells
**Problem:** `currentCapital` became `null` after position close
**Impact:** Next buy attempt: `Position size = null × 50% = NaN` → "Invalid amount"
**Fix:** Call `updateCapitalFromChain()` after every successful sell
**Commit:** 2462c91 - "Fix capital tracking after sells (NaN position size bug)"

### Bug #6: Price Calculation in Position Monitoring
**Problem:** P&L calculated wrong, showed -100% when actual was -20%
**Fix:** Added proper error handling in `updateCapitalFromChain()`, better logging
**Commit:** 1661502 - "Add error handling to updateCapitalFromChain"

### Key Lessons Learned

**42. Slippage is Real and Must Be Verified**
- Jupiter quotes are ESTIMATES, not guarantees
- 1-2% slippage is normal on smaller tokens
- Always verify actual received amount from blockchain
- Trusting quotes = guaranteed failure on sells
- **Lesson:** For financial applications, verify every on-chain operation

**43. Token Programs Matter**
- Standard SPL vs Token-2022 are different programs
- BUDI/fartbutt used Token-2022 (newer extension program)
- Must check both `TOKEN_PROGRAM_ID` and `TOKEN_2022_PROGRAM_ID`
- Initial checks missed tokens because wrong program ID
- **Lesson:** Know your token standards and check all variants

**44. Decimals Are Not Universal**
- Most Solana tokens: 9 decimals
- Many pump.fun tokens: 6 decimals
- Hardcoding decimals = 1000x calculation errors
- Must fetch per-token and store with position
- **Lesson:** Never hardcode token-specific values

**45. Precision Loss Compounds**
- Float → String → Float loses precision
- "52698.67" → 52698670000 vs actual 52698666486
- 3,514 base unit error = "Insufficient funds"
- Store raw integers, display only for humans
- **Lesson:** Financial calculations require integer math

**46. Side Effects Hidden in State**
- Position had all fields EXCEPT `side`
- Logic checked `if (position.side === 'long')` → always false
- Silent failure - no error, just wrong behavior
- **Lesson:** Validate object structure, don't assume fields exist

**47. Aggressive Settings on Volatile Tokens = Learning Tuition**
- 50% confidence (3/6 conditions) caught many entries
- Low-cap tokens (fartbutt) had wild swings
- Combination = many trades, mostly losses
- Cost: $11.44 (learning tuition)
- Gained: Complete understanding of all failure modes
- **Lesson:** Test on stable tokens with conservative settings first

**48. Infrastructure First, Then Strategy**
- Spent 4 hours fixing bugs, 10 minutes on strategy
- All losses were from working infrastructure + bad market timing
- If infrastructure was still broken, couldn't test strategy at all
- **Lesson:** Solid foundation enables experimentation
