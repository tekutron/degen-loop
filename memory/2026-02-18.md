## Critical Discovery: Price Bug (Not a Rug!)
**Time:** 21:00-21:36 PST

### Initial Diagnosis (WRONG)
- Thought: WAR token was rugged/illiquid
- Evidence: -98% losses displayed, "Insufficient funds" errors
- Conclusion: Dead token, bot lost 87% capital

### User Correction: "Check the coin again it has plenty of liquidity"
- User was RIGHT - questioned the diagnosis
- Checked DexScreener: WAR has $677K liquidity, $1.2M volume
- This was NOT a rug pull

### Real Problem: Price Calculation Bug
**Line 350 in jupiter-swap.mjs:**
```javascript
const price = amountOut / amountIn;  // 38,853,786 / 14,125,556 = 2.75
```

Divided raw base units by raw lamports → meaningless ratio

**Real transaction:**
- Spent: 0.014 SOL ($1.20)
- Received: 38.85 WAR
- Real entry: $0.031 per WAR
- Displayed entry: $2.75 per WAR (93x error!)

**Impact:**
- Displayed: -98% losses
- Reality: -6% losses
- Panic was caused by display bug, not actual trading disaster

## Key Lessons

### 1. Verify Before Assuming
- User questioned diagnosis: "Check the coin again"
- User was RIGHT - WAR had $677K liquidity
- Don't assume rug pull without checking on-chain data

### 2. Display Bugs ≠ Actual Losses
- Displayed -98% but reality was -6%
- Always verify with on-chain transactions
- Price calculations are CRITICAL

### 3. Listen to User Feedback
- User knew something was wrong
- Checking DexScreener proved it
- Saved us from wrong conclusions

### 4. Raw Data > Converted Data
- String conversions lose precision
- Raw base units prevent rounding
- Store exact values from API responses

### 5. Required Fields Must Be Complete
- Missing `price` broke P&L
- Missing `side` broke exits
- Always return complete objects
