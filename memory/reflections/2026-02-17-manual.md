# Manual Reflection - Feb 15-17, 2026

**Period:** 3 days of intensive wickbot development and troubleshooting
**Key Theme:** Infrastructure maturity - moving from "it works" to "it's usable"

## Major Accomplishments

### 1. Speed Upgrade (Feb 16 evening)
**Achievement:** Built O(1) incremental indicators in pure JavaScript
- Pivoted from Python Hexital to pure JS (environment constraints)
- Polling: 20s → 5s (4x faster)
- Total reaction time: 20s → 400ms (80x improvement!)
- All indicators update incrementally (RSI, MACD, BB, EMA)

**Impact:** Bot can now catch dips/tops within 1-2 seconds instead of missing them entirely.

**Lesson:** When a solution is blocked (Python env), pivoting quickly is better than forcing it. Pure JS ended up being simpler AND faster.

### 2. Dashboard Evolution (Feb 15-17)
**Journey:** From broken to beautiful to functional

**Timeline:**
- Feb 15: Basic dashboard with charts (Lightweight Charts library)
- Feb 16: Replaced chart with live signal feed (better performance)
- Feb 17: Fixed WebSocket, removed redundant UI, cleaned syntax errors

**Critical debugging today:**
- WebSocket hardcoded to localhost (blocked remote access)
- JavaScript syntax error preventing entire script load
- User couldn't start bot → traced to browser console errors

**Lesson:** When users say "nothing happens," check browser DevTools first. Also, browser caching fights against rapid iteration - hard refresh is essential.

### 3. API Reliability Work (Feb 15-16)
**Problem:** Price monitoring failures killing trades
- Bitquery timeouts during Feb 14 live test
- Jupiter DNS failures during Feb 16 session
- Both APIs became single points of failure

**Solutions implemented:**
- Moralis as primary price source (600ms, reliable)
- Raydium swap as Jupiter backup (attempted, API breaking changes)
- Multi-source price waterfall (Moralis → Bitquery → DexScreener)

**Status:** Partially complete. Moralis working great. Raydium integration blocked by SDK changes.

**Lesson:** External APIs will fail. Always have fallbacks. Trading bots need redundancy.

## Patterns Noticed

### Good Patterns 🟢

1. **Test-driven iteration**
   - 1-min test → 5-min test → identify issues → fix → repeat
   - Dry runs catch bugs before risking capital
   - Short tests = fast feedback loop

2. **Git discipline**
   - Every fix gets committed with clear message
   - Easy to rollback when things break
   - Daily logs track decision context

3. **Infrastructure thinking**
   - Desktop shortcuts (usability)
   - Balance tracking (visibility)
   - Dashboard server (monitoring)
   - Not just "make it work" but "make it easy to use"

4. **Pivot when blocked**
   - Python env locked? Use pure JS instead.
   - Jupiter down? Try Raydium.
   - Chart library slow? Replace with simple log feed.

### Areas for Improvement 🔴

1. **Browser-side debugging gaps**
   - Didn't immediately think to check browser console
   - Assumed server-side issue when it was client-side
   - Need to build "check DevTools first" instinct

2. **Testing in realistic conditions**
   - All recent tests during flat markets (0.01-0.07% moves)
   - Haven't validated speed upgrade in real volatile conditions
   - Risk: Optimizing for wrong scenario

3. **Documentation lags behind code**
   - Dashboard changes fast, README doesn't keep up
   - User confused about how to use dashboard
   - Need to update docs after each major change

4. **Incomplete fallbacks**
   - Raydium integration started but not finished
   - Left in half-working state when Jupiter came back
   - Should either complete or remove, not leave dangling

## Insights & Learning

### Technical Insights

1. **Incremental indicators are game-changers**
   - O(1) update time vs O(n) recalculation
   - Makes 5s polling viable (was 20s before)
   - Enables real-time trading strategies

2. **WebSocket auto-detection pattern**
   ```javascript
   // ❌ Bad: Hardcoded
   ws = new WebSocket('ws://localhost:3000')
   
   // ✅ Good: Auto-detect
   ws = new WebSocket(`ws://${window.location.host}`)
   ```
   Works from any IP, no config needed.

3. **Orphaned code after refactoring**
   - Empty function stubs can hide broken code
   - Syntax errors prevent entire script load
   - Always test after removing/stubbing functions

4. **Browser caching vs rapid development**
   - Standard refresh keeps old HTML/JS
   - Hard refresh (Ctrl+Shift+R) required
   - Can lose 15+ minutes troubleshooting "fixes that don't work"

### Process Insights

1. **User feedback is gold**
   - "Dashboard not working" led to 3 separate bugs discovered
   - Each bug was invisible from server logs
   - Need to ask "what do you see in browser console?"

2. **Flat markets are poor test environments**
   - Bot correctly rejects trades (good!)
   - But can't validate trade execution (bad!)
   - Need to test during US session (9am-4pm EST) for real volatility

3. **Infrastructure work feels slow but pays off**
   - Desktop shortcuts seem trivial
   - Balance tracking seems obvious
   - But they reduce friction for actual trading later
   - "Make it easy to use" = "you'll actually use it"

### Strategic Insights

1. **Speed matters more than complexity**
   - 80x faster reaction time > fancy indicators
   - Catching breakouts early > predicting them perfectly
   - Simple fast >> complex slow

2. **Reliability > features**
   - Moralis integration more valuable than new indicators
   - Fallback swaps more important than new strategies
   - Bot that runs all night > bot with cool features that crashes

3. **Usability unlocks usage**
   - Dashboard makes monitoring easy
   - Desktop shortcuts make starting easy
   - Easy = you'll actually run it = you'll actually learn from it

   - Test from different browsers/devices
   - Test with API failures (chaos engineering)

3. **Completion over starting**

   - "Done" means tested, committed, documented

### Collaboration Patterns

1. **Assume less technical knowledge**
   - "Refresh the page" → "Press Ctrl+Shift+R"
   - "Check console" → "Press F12, click Console tab"
   - Be explicit, not assumptive

2. **Gather environmental context early**
   - "What browser are you using?"
   - "Are you on the same machine or remote?"
   - "What errors do you see?"

3. **Celebrate small wins**
   - "Dashboard works!" feels good
   - Builds momentum for next session
   - Positive reinforcement beats grind
